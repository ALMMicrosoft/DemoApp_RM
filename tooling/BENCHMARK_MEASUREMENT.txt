Measuring CodeQL + Copilot detection rate on these five PRs
============================================================

Scope
  Each PR adds exactly one labeled SAST-BENCHMARK pattern under src/benchmark/
  (and pr-05 adds public/benchmark-pr05/index.html). Synthetic secret only — not a real credential.

Setup
  1. npm install
  2. powershell -ExecutionPolicy Bypass -File .\create-benchmark-prs.ps1
  3. Create a remote repo; git remote add origin <url>; git push -u origin --all
  4. Open five pull requests: each benchmark/* branch into main.
  5. CodeQL: this repo includes .github/workflows/codeql.yml (javascript + default queries plus security-extended via `+security-extended`).
     After each PR, check the Security tab → Code scanning alerts (or the PR Checks tab).
  6. Copilot: enable Copilot code review / PR comments in your org if you use them for detection scoring.

Detection rate (CodeQL)
  - Denominator: 5 intentional issues (or split by CWE if you prefer).
  - Numerator: PRs where CodeQL shows at least one new alert attributable to the benchmark change.
  - Record per-PR: alert rule id, precision, and whether it points at the introduced line.

Detection rate (Copilot)
  - If your org uses Copilot for PRs, count comments or suggestions that name SQLi / secret / XSS
    on the changed hunks. Define ahead of time whether partial mentions count as true positives.

Notes
  - CodeQL packs differ by query suite (security-extended vs default). Compare runs using the same workflow.
  - DOM XSS in static HTML may be reported under different queries than server-side XSS; that is part of what you are measuring.
